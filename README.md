# hvf-mac opam repository

An opam overlay that carries the forks needed to build and run MirageOS
unikernels on Apple Silicon Macs (macOS 26+), with the `solo5-hvt` tender
running on Hypervisor.framework.

| Package | Version | Why it is forked |
| --- | --- | --- |
| `solo5` | 0.13.0+hvf.N | HVF backend for `solo5-hvt`, sandbox, macOS toolchain; user memory (`USER_MEMORY`) and `-z solo5-text-start` |
| `ocaml-solo5` | 1.3.4+hvf.N | builds on a macOS host; OCaml 5.5.2 patches |
| `mirage`, `mirage-runtime` | 4.11.2+hvf.N | accept solo5 0.13; `register ~user_memory ~text_start` for hvt |
| `mirage-crypto*` | 2.4.1+hvf.N | entropy self-test on 24 MHz ARM timers |
| `gmp` | 6.3.0-1+hvf.N | build with LLVM binutils and as a macOS host library |
| `opam-monorepo` | 0.5.0+hvf.N | honour `OPAMSWITCH`, so `make depends` works without a global switch |

Packages are generated by `./generate.sh` from the fork checkouts next to
this directory, each pinned to an exact commit. The default source base is
`git+https://github.com/rococompute/`, so the checked-in overlay works independently
of the checkout location. Commit fork changes before regenerating; metadata is
read from each pinned commit, and package revisions must increase when installed
contents change.

The fork repositories currently require GitHub repository access. Git must be
authenticated for their HTTPS URLs, including when opam fetches sources; for
example, run `gh auth login` and `gh auth setup-git` first.

## Use

```sh
brew install llvm lld aarch64-elf-gcc
opam switch create mirage-hvf ocaml-base-compiler.5.5.2
opam repo add hvf-mac <path or URL of this repository> --this-switch --rank=1
opam install mirage ocaml-solo5 solo5
```

Unikernels then build as usual: `mirage configure -t hvt && make`. Keep this
repository in the switch's selection while running `make depends` so that
`opam monorepo lock` picks the forked packages.

Regenerate from an initialized superproject checkout:

```sh
./generate.sh
opam update hvf-mac
```

For an offline local development overlay, use
`FORKS_URL="git+file://$(cd .. && pwd)/" ./generate.sh`. Keep that output local;
run `./generate.sh` again before publishing. Push the pinned fork commits before
publishing the overlay or the superproject gitlinks.
